# Состояние четырёх задач на 15 октября 2026 года

Цель: кроссфейд 3–10 секунд и экран «Плавный переход» в штатной RetailOS 1.3 iPod Video 5.5G 30 GB. Этот файл описывает только подтверждённые результаты. Готового образа для установки пока нет.

## 1. Путь от декодера до I²S

Windows показывает подключённый Apple iPod как USB-диск 1 размером 30 005 821 440 байт с MBR. Серийный номер совпал с номером, указанным владельцем; номер намеренно не записан в публичный репозиторий. Номер диска может измениться при переподключении.

В OSOS с SHA-256 `784ae3d5540fd2f89e8c947b93629e97f62a06dc311d9745aab143e4db6bb251` подтверждена цепочка настройки I²S: литерал аппаратной базы `0x70002800` в `OSOS+0x25df58` → загрузка в `+0x25de8c` → конструктор `+0x18c85c` → конструктор `+0x1a3080` → vtable `+0x66d338` → буферный callback `+0x25a614`. Этот callback работает с двумя половинами одного буфера по `0x20000` байт. При отсутствии данных он очищает участок вызовом `+0x7ccd0`; затем передаёт указатель и длину дальше виртуальным методом или через `+0x1a2d60`. Это не является доказательством доступа к началу следующей песни.

Дополнительный разбор `+0x132b14` и `+0x132c18` показывает чтение пар указатель/длина из очереди. Метод `+0x132b08` задаёт поле объекта `+0x30`; прямые вызовы найдены в `+0x18bf8c` и `+0x1b7568`. Это уточняет устройство буферной очереди, но не связывает очередь с двумя музыкальными декодерами. Не установлены конкретный музыкальный producer, формат PCM, момент предварительного открытия следующего трека и канал DMA.

## 2. Микшер в реальном звуковом тракте

На компьютере есть работающий Python-прототип линейного смешивания PCM16 WAV. Он не вызывается прошивкой. До подтверждения интерфейса декодера, формата выходных блоков и доступности второго потока нельзя корректно подменить I²S callback. Патч аудиотракта не собран.

## 3. Штатный экран и сохранение настройки

Утверждённый макет показывает русскую надпись, прямой ползунок с круглым бегунком, значения 3–10 секунд и управление Click Wheel. В публичном описании другого патча RetailOS 1.3 указаны Settings Menu ID 24598, общий ресурсный lookup `OSOS+0x21f254` и vtable get/set объекта настроек `OSOS+0x66c94c/+0x66c950`. Автор использовал переключатель On/Off; исходный код пока не опубликован. Эти сведения — отправная точка для изучения ресурсов, а не реализованный экран или готовый способ хранения числового значения.

## 4. Сборка, установка и проверка

Резервные образы в каталоге проекта и в корне `D:\` имеют одинаковый размер 98 574 336 байт и SHA-256 `010bda520671d86a5a2cb010b57ee4484c980e54d97eb3e12621e08cde0423a3`. Они не менялись. Установка на подключённый iPod не выполнялась: отсутствует проверенный патч OSOS/RSRC и отдельный собранный образ.

Перед установкой нужны: воспроизводимая сборка из точного OSOS 1.3; проверка всех изменённых областей и контрольных сумм; загрузка и UI-проверка; аудиопроверка на переходе двух треков и при перемотке/смене частоты/отмене; способ возврата к исходной прошивке. Доступный эмулятор 5.5G RetailOS пока не моделирует звуковой кодек, поэтому не подтверждает кроссфейд на слух.

## Сверка адресов внешней спецификации

Публичная спецификация с именем `iPod_5_5G_Video_Enhanced_25_1_3.md` использует смещения относительно полного IPSW payload; локальный OSOS внутри него начинается с `0x4800`. Для пяти строк проверено соответствие `offset_spec - 0x4800 = offset_OSOS`: `AudioCodecs` `0x17a888 → 0x176088`, `TrackCacheReadTask` `0x99174 → 0x94974`, `StreamCacheReadTask` `0x210664 → 0x20be64`, `MP3ExampleTask` `0x16f904 → 0x16b104`, `GotoBackToIdleCommand` `0x4b8c04 → 0x4b4404`. При этом общий размер и хеш бинарника в спецификации отличаются от локального payload. Табличные названия функций там нельзя принимать без проверки дизассемблированием: некоторые записи указывают на строки.
