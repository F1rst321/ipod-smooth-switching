# Изолированный PCM-микшер

В `src/crossfade_mixer.c` реализован компактный stereo/mono микшер PCM16 для
двух уже декодированных блоков. Он плавно меняет gain от A к B за заданное
число кадров, сохраняет точный прогресс между блоками, завершает переход на
точных крайних значениях и поддерживает обработку на месте. Длительность
задаётся вызывающим кодом; для настроек 3–10 секунд он должен передать
`частота_дискретизации × выбранные_секунды`.

`src/crossfade_pcm_ring.c` добавляет non-blocking SPSC очередь PCM16 для
декодированного B. Память заранее выделяется одним блоком через штатный heap
RetailOS, затем этот блок передаётся функции инициализации; read/write операции
не выделяют память и не ждут.
Для 4 блоков по 1152 кадра stereo PCM16 очередь занимает 18 456 байт: 18 432
байта данных, один sentinel-кадр и заголовок. Если штатный аллокатор откажет,
инициализация вернёт нулевой указатель; вызывающий код должен оставить штатное
воспроизведение без кроссфейда. Буфер освобождается только после остановки
producer-а и consumer-а.

`ipod_crossfade_pcm_ring_create()` вызывает allocator RetailOS 1.3 по адресу
`OSOS+0x25a974` (runtime `0x1025a974`), а destroy вызывает
`OSOS+0x25a8f4` (runtime `0x1025a8f4`). Оба вызова должны выполняться из
обычной задачи, до/после использования кольца аудиопутём. Эмулятор перехватывает
эти адреса заглушками и проверяет размер запроса, отказ allocator-а и очистку
неподходящего блока; реальная доступность heap во время playback не измерена.

Код собирается для ARM7TDMI / ARMv4T Thumb в существующее проверенное окно
OSOS `0x10712000..0x107161a4`. Увеличивать OSOS на диске для PCM не нужно:
будущая реализация должна запросить буферы через runtime heap. Расчётный
кандидат с четырьмя PCM-блоками, заголовком/сентинелом очереди, минимумом 164
байта на MP3 sync object и `0x700`-байтовым stack request составляет
56 500 байт. HIBE-снимок простоя
показывает крупнейший свободный блок 4 641 944 байта, но такой же запас во
время воспроизведения не измерен. Фактический размер stack allocation,
stream/cache и другие затраты неизвестны; сам резерв и второй producer пока
не подключены.

Сначала можно скачать официальный Arm GNU Toolchain 14.3 и проверить его SHA-256
в игнорируемом `build/`:

```powershell
.\tools\bootstrap_arm_toolchain.ps1
py .\tools\build_crossfade_mixer.py
```

Сборка создаёт `.elf`, `.bin`, карту линковки и журнал в игнорируемом
`build/crossfade-mixer/`. Проверить экспортированные функции и машинное
поведение можно эмулятором Unicorn:

```powershell
py -m pip install --target .\build\pydeps -r .\requirements-emulation.txt
$env:PYTHONPATH = (Join-Path (Get-Location) 'build\pydeps')
py .\tools\verify_crossfade_mixer.py
```

Эмулятор проверяет арифметику микшера, операции кольцевой очереди и контракт
вызова heap API. Этот payload
пока не вызывается из RetailOS: не добавлены hook в штатный playback callback,
producer PCM для следующей песни, экран настройки, сохранение значения и
lifecycle runtime-аллокации. Поэтому `.bin` остаётся промежуточным кодовым
модулем и не предназначен для прошивки или инъекции как готовая прошивка.
